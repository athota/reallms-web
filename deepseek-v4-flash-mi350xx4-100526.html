Two core services

One service, two ways to work

REALLMS is a shared, curated LLM service. Use the browser-based Chat to think and explore, or the API to build models into your own workflows and services.

REALLMS Chat

reallms.rescloud.iu.edu

A web-based chat application built on the Open WebUI platform with a vLLM back end. Available to anyone with an IU account — no separate account needed.

Open WebUI vLLM Approved for Critical research data & PHI
Launch REALLMS Chat → About REALLMS Chat (IU KB) →

REALLMS API

reallms.rescloud.iu.edu/direct/v1

An OpenAI-compatible API that lets IU researchers, faculty, and staff integrate LLMs into their workflows and services at no cost. Access is requested through RT Projects. The service is in beta.

LiteLLM routing vLLM backend RT Projects allocation
About REALLMS API (IU KB) → Request access in RT Projects → How to use RT Projects (IU KB) →
Data classification: Both REALLMS Chat and the API are approved for use with Critical research data and PHI. Chat conversation data persists in the web app; data sent to the API is not stored. See IU's DM-01 policy.

API, IDEs & harnesses

REALLMS API · OpenAI-compatible

Point any OpenAI-compatible tool at the REALLMS API to bring IU-hosted models into your software, scripts, and coding agents.

  • 🤖
    IDEs & extensionsUse the OpenAI-compatible base URL in editors and AI coding extensions.
  • 💻
    Coding harnessesConnect CLI agents such as Codex and OpenCode to REALLMS models.
  • ⚙
    Workflows & servicesCall /chat/completions, /completions, /embeddings, and /rerank from your own code.
  • 🔍
    Retrieval pipelinesPair embedding and reranking models to build search and RAG systems.

Get an API key

From RT Projects to a REALLMS API key

API access is granted through an RT Projects allocation. Follow the five steps below — once your allocation is approved, you create your own key from the allocation page.

1

Visit RT Projects

Go to projects.rt.iu.edu and sign in with your IU account.

2

Create a project

Follow the RT Projects guide to set up a project for your work.

3

Request allocation

Request a REALLMS API allocation for that project.

4

Get approved

Once approved, open your allocation's page in RT Projects.

5

Create your key

Generate a personal API key and start calling the API.

Keys are personal. Each key is owned only by you. To give teammates access, add them to your project and allocation, then have each person create their own key. Full instructions: REALLMS API KB article.

Connect your tools

Codex & OpenCode setup guides

Both tools speak the OpenAI API. Point them at the REALLMS base URL with your personal API key. These guides use Qwen3-Coder-Next as the example model — swap in any text model from the list above.

OC

OpenCode

Open-source AI coding agent for the terminal. Uses a custom OpenAI-compatible provider.

You need: an approved REALLMS allocation, your personal API key, and OpenCode installed. See the OpenCode provider docs and config docs.

1. Install OpenCode

Install via the official installer or your package manager.

Shell
curl -fsSL https://opencode.ai/install | bash
opencode --version

2. Add your REALLMS key

Store your key as an environment variable, or use the /connect flow with a custom provider.

Shell
export REALLMS_API_KEY="<your-personal-api-key>"

# Verify the key and list models
curl -X GET https://reallms.rescloud.iu.edu/direct/v1/models \
  -H "Authorization: Bearer $REALLMS_API_KEY"

3. Configure the custom provider

Create opencode.json in your project (or ~/.config/opencode/opencode.json globally). The @ai-sdk/openai-compatible package lets OpenCode talk to any OpenAI-compatible endpoint.

opencode.json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "reallms": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "REALLMS at IU",
      "options": {
        "baseURL": "https://reallms.rescloud.iu.edu/direct/v1",
        "apiKey": "{env:REALLMS_API_KEY}"
      },
      "models": {
        "Qwen3-Coder-Next": { "name": "Qwen3 Coder Next" },
        "gpt-oss-120b": { "name": "GPT OSS 120B" },
        "glm-5.2": { "name": "GLM 5.2" },
        "gemma-4-31B-it": { "name": "Gemma4 31B" }
      }
    }
  },
  "model": "reallms/Qwen3-Coder-Next"
}

4. Run it

Launch OpenCode, then use /models to confirm the REALLMS models appear.

Shell
opencode
# In the TUI:
/models

CX

Codex CLI

OpenAI's coding agent. Uses a custom model provider in ~/.codex/config.toml.

You need: an approved REALLMS allocation, your personal API key, and Node.js/npm. See the Codex advanced config docs.

1. Install Codex

Install the CLI globally and confirm the version.

Shell
npm install -g @openai/codex
codex --version

2. Set your REALLMS key

Export your personal key in the shell where you'll run Codex.

Shell
export REALLMS_API_KEY="<your-personal-api-key>"

curl -X GET https://reallms.rescloud.iu.edu/direct/v1/models \
  -H "Authorization: Bearer $REALLMS_API_KEY"

3. Define the REALLMS provider

Add a custom model provider to your user-level ~/.codex/config.toml. Codex reads the key from the env_key you name. The REALLMS API is OpenAI-compatible and uses the Chat Completions wire API.

~/.codex/config.toml
model = "Qwen3-Coder-Next"
model_provider = "reallms"

[model_providers.reallms]
name = "REALLMS at IU"
base_url = "https://reallms.rescloud.iu.edu/direct/v1"
env_key = "REALLMS_API_KEY"
wire_api = "chat"

4. Launch Codex

Run Codex from your project folder. It will use the REALLMS model you selected.

Shell
cd /path/to/your/project
codex
Heads-up: the IU KB documents the REALLMS API as OpenAI-compatible Chat Completions. If your Codex version requires the Responses API and a direct connection fails, a local LiteLLM bridge can translate Responses to Chat Completions. Verify endpoints against the IU KB article.
