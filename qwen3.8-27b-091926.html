Two ways in

The two core components of REALLMS

Same models, same on-prem GPUs — pick the doorway that fits your work: a ready-made chat interface, or direct API access to build on.

REALLMS Chat

reallms.rescloud.iu.edu
Any IU account

An LLM-powered chat service built on the Open WebUI platform with a vLLM back end. Anyone with an IU account can sign in and start — no separate account, no setup.

  • Choose among 4 chat models — including 256K-context options
  • Save multiple chats, upload documents for context, and generate images
  • Folder support — drop documents, collections, and a custom prompt into a folder; every chat inside inherits them
  • Knowledge collections shared with groups, plus Google Drive & OneDrive as sources (contact the RADL team to get set up)
Open REALLMS Chat → IU KB overview

REALLMS API

reallms.rescloud.iu.edu/direct/v1
Beta

For IU researchers, faculty, and staff to integrate large language models into their own workflows and services — at no cost. Uses LiteLLM for request routing and a vLLM back end for serving and managing models.

  • OpenAI-compatible endpoints: /models, /chat/completions, /completions, /embeddings, /rerank
  • Access is granted through an RT Project allocation via projects.rt.iu.edu
  • Your key is personal — invite teammates to your project, and each creates their own key
  • Approved for Critical research data and PHI; data sent to the API is not stored

Set up your tools ↓
OpenAI-compatible

One base URL, five endpoints

Point any OpenAI-compatible client at the base URL, set your key as a bearer token, and go. Full details live in the REALLMS API documentation.

Base URL https://reallms.rescloud.iu.edu/direct/v1
GET/models

List every model currently available on the service.

POST/chat/completions

Chat with all four general-purpose models.

POST/completions

Raw completions across the same four models.

POST/embeddings

Vectors via Qwen3-Embedding-8B or embeddinggemma-300m.

POST/rerank

Passage re-ranking with Qwen3-Reranker-8B.

hello-reallms.sh — straight from the IU KB 
# List available models
curl -X GET https://reallms.rescloud.iu.edu/direct/v1/models \
  -H "Authorization: Bearer <API-KEY>"

# Send a message to a model
curl -X POST --location https://reallms.rescloud.iu.edu/direct/v1/chat/completions \
  --header 'Authorization: Bearer <API-KEY>' \
  --header 'Content-Type: application/json' \
  --data '{
  "model": "gemma-4-31B-it",
  "messages": [
    { "role": "user", "content": "Why is the sky blue?" }
  ]
}'

Running at scale? If your workflow needs high throughput, UITS recommends the HPC LLM platform on IU's research supercomputers — heavy usage of the API may result in rate-limiting. The service is in beta and may see unexpected downtime and changes.

Plug REALLMS into your tools

Set REALLMS_API_KEY to the key you created in RT Projects, then add a provider pointing at the base URL above.

Codex CLI

OpenAI Codex CLI · ~/.codex/config.toml

1. Add a REALLMS provider to ~/.codex/config.toml and 2. export your key — then just run codex.
~/.codex/config.toml 
model_provider = "reallms"
model = "gpt-oss-120b"

[model_providers.reallms]
name = "REALLMS (IU)"
base_url = "https://reallms.rescloud.iu.edu/direct/v1"
wire_api = "chat"
env_key = "REALLMS_API_KEY"

# in your shell, before running codex
# export REALLMS_API_KEY=your-key

opencode

opencode · opencode.json

1. Register REALLMS as an OpenAI-compatible provider in opencode.json, then 2. select any model as reallms/<model>.
opencode.json 
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "reallms": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "REALLMS (IU)",
      "options": {
        "baseURL": "https://reallms.rescloud.iu.edu/direct/v1",
        "apiKey": "{env:REALLMS_API_KEY}"
      },
      "models": {
        "gpt-oss-120b":     { "name": "GPT OSS 120B" },
        "Qwen3-Coder-Next": { "name": "Qwen3 Coder Next" },
        "gemma-4-31B-it":   { "name": "Gemma 4 31B" },
        "glm-5.2":          { "name": "GLM 5.2" }
      }
    }
  }
}

Any OpenAI-compatible client

Python · curl · your framework

Every OpenAI SDK works as-is — swap the base_url and api_key, pick a model ID, and you're on IU infrastructure.
reallms_client.py 
import os
from openai import OpenAI

client = OpenAI(
    base_url="https://reallms.rescloud.iu.edu/direct/v1",
    api_key=os.environ["REALLMS_API_KEY"],
)

resp = client.chat.completions.create(
    model="gpt-oss-120b",
    messages=[{"role": "user", "content": "Why is the sky blue?"}],
)
print(resp.choices[0].message.content)
Good to know

The fine print, made friendly

Your data stays on campus

All infrastructure runs in the IU Data Center. Chats live in the REALLMS Chat web app and aren't used for analysis; data sent to the API is not stored. Both services are approved for Critical research data and PHI.

24×7, with light maintenance

Generally available around the clock. Scheduled model and security updates happen in UITS-RT maintenance windows (second Sunday, 7am–7pm ET) with minimal, usually under-two-hour, downtime.

Get help, request models

Questions? Contact the UITS REALLMS team or the REALLMS help desk. Want a different model? Fill out the REALLMS Model Request Form. Join the #reallms channel on the IU HPC & AI User Community Slack to connect with the team and other researchers.
