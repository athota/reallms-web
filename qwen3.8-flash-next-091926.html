Codex CLI

custom provider via a model_profile in config.toml

Add a REALLMS profile to ~/.codex/config.toml, export your key, then run with the profile.

~/.codex/config.toml
# use: codex --profile reallms
model_provider = "reallms"
model          = "Qwen3-Coder-Next"  # /models for IDs

[model_providers.reallms]
name     = "IU REALLMS"
base_url = "https://reallms.rescloud.iu.edu/direct/v1"
env_key  = "REALLMS_API_KEY"
wire_api = "chat"
terminal
export REALLMS_API_KEY="<your RT Projects key>"
codex "refactor the test suite to pytest"

Prefer a second provider? Keep your OpenAI default and pass --profile / --config model_provider=reallms per run. See the Codex config reference ↗

opencode

custom OpenAI-compatible provider in opencode.json

Declare REALLMS as a provider using @ai-sdk/openai-compatible. Store the key with /connect, or read it from the environment as shown.

opencode.json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "iu-reallms/Qwen3-Coder-Next",
  "provider": {
    "iu-reallms": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "IU REALLMS",
      "options": {
        "baseURL":
          "https://reallms.rescloud.iu.edu/direct/v1",
        "apiKey": "{env:REALLMS_API_KEY}"
      },
      "models": {
        "Qwen3-Coder-Next": { "name": "Qwen3 Coder Next" },
        "glm-5.2":           { "name": "GLM 5.2" },
        "gemma-4-31B-it":    { "name": "Gemma4 31B" },
        "gpt-oss-120b":      { "name": "GPT OSS 120B" }
      }
    }
  }
}
terminal
export REALLMS_API_KEY="<your RT Projects key>"
opencode
# inside the TUI:  /models → iu-reallms/*

Good to know

Built for research use.

🔒
Approved for PHI

Both services are approved for Critical research data and PHI under DM-01. Questions on data sensitivity? Email the Data Steward for Research Data (datard@iu.edu).

🗂️
Chats stay in the browser app

Chat conversations are kept in the web app for persistence and aren't used for internal analysis. Temporary chats aren't stored, and data sent to the API is not stored.

📉
Model lifecycle

One long-term supported general-purpose model gets ≥3 months' removal notice; all others get 30 days. Need a specific model? Use the REALLMS Model Request Form.

⚡
High-throughput jobs

The API is a shared resource; heavy use may be rate-limited. For big batches, UITS recommends HPC LLMs on IU's research supercomputers.

🔧
Maintenance & uptime

Generally available 24×7 on scheduled maintenance (second Sunday monthly, 7am–7pm ET) with minimal downtime. API is in beta — expect occasional unexpected downtime and change.

💬
Help & community

Ask in the IU HPC and AI User Community Slack #reallms channel, or reach the UITS REALLMS team via the REALLMS contact form (Mon–Fri, 8am–5pm ET).
